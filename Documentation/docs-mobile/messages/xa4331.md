# .NET for Android error XA4331

## Example message

```
error XA4331: Could not generate JNI remapping asset from 'r8-jni-remap.xml' to 'jni-remap.bin': ...
```

## Issue

The build could not read JNI replacement XML, write its versioned binary data, or
wrap that data in the ABI-specific `libandroid_runtime_blobs.so`.
The diagnostic includes the input and output paths and the underlying failure.
Missing input files, malformed XML, invalid UTF-8 strings, or an unwritable output
directory are errors, not empty remapping data.

The asset is written to a temporary sibling and replaces the output only after
the write succeeds. A failed write does not leave a partial asset or change an
existing asset's timestamp, so a subsequent build can safely retry.

Applications without replacement entries receive a valid empty binary payload.
Missing source signatures remain wildcards, and missing target signatures retain
the signature used by the caller.

The data-only library exports a single remapping payload symbol. The native loader
first bounds its fixed-size header within a read-only ELF load segment, then checks
the declared payload size against that independently discovered mapping. It is
retained for the process lifetime, without Java byte-array
staging or a managed payload copy. The producer validates all entries, UTF-8 and
table ordering. Startup checks only the fixed-size header and table bounds;
visited strings and pointers are checked before lookup returns them. Invalid
unused entries are not scanned at startup.

## Solution

Fix the reported input or output path and the underlying failure. If the XML was
generated by .NET for Android, clean and rebuild the application. If the error
persists, [report an issue](https://github.com/dotnet/android/issues/new/choose)
with a binary build log and the affected remapping XML.
