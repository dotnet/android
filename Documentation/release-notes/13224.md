### Java interoperability

With the trimmable type map (`AndroidTypeMapImplementation=trimmable`), explicit
`[Export]` and `[ExportField]` declarations are Java-to-managed entry points,
including when `TrimMode` is `full`. Their declaring Java peer, exported
callbacks, and constructors exposed by the Java callable wrapper are preserved
even when there are no managed callers. This applies to both CoreCLR and
NativeAOT, so Java source can instantiate the wrapper and call its exports
without additional managed preservation declarations.

This does not preserve the entire declaring assembly or unrelated managed
members. `[Register]` alone does not make an otherwise unreferenced peer an
entry point, and a derived peer does not become an entry point merely by
inheriting an exported method.

.NET 11 applications using these attributes must still reference
`Mono.Android.Export`. This fix does not change the legacy type map behavior.
